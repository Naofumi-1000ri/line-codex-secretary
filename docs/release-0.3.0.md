# 0.3.0公開統合の記録

2026-09-11。公開main `022ee11580d73bca6d758be783e4769397fa4f5c`（Windows対応を含む0.1.0）を基準に、元チェックアウトに未コミットで存在していた画像・動画・整理・会話UXの実コードを統合しました。今回はメモからの再実装ではなく、元ソースとテスト・migration 0002〜0004を根拠にしています。

## 含まれる機能

- LINE画像・動画の認証付きストリーム取得、原ファイル保存、ffmpegによるプレビュー、一覧・要約の保存。
- 画像セット・連続した文章の一括取得、処理中の追加分と先の結果の引き継ぎ、通常／詳細通知、コピー整理。
- Windows DPAPIとMac Keychainを維持。Windows予約名・無効文字の拒否、パス区切り、junction境界の回帰検査。
- Worker・Agent・全workspace package・lockfileは0.3.0、DB schema4。共通定数と整合テストでずれを検出。Agent起動時のWorker / schema確認、旧Agentの426拒否。
- 同時刻の文章はランダムな受付番号ではなく受付順で処理。配信未確認の結果をAgentログでLINE配信成功と表示しない。

公開テンプレートの個人アカウント・既存D1 IDをプレースホルダーに置換しました。実際の設定・鍵・生成メディア・配布用動画・スクリーンショットは取り込んでいません。元チェックアウトの未コミットファイルは編集していません。

## 検証

ローカルとGitHub ActionsのMac / Windowsで型チェック、単体テスト、実ffmpegのJPEG・PNG・MP4プレビューとコピー、実workerd / D1統合、Worker dry-runを検査します。CIはNode 22.18.0、Codex CLI 0.153.4。Windowsでは実DPAPI、両OSで認証不要のCodex App Server初期化・停止も含みます。最終結果はPRに記録します。

Worker統合ではschema1の既存ジョブを残してschema4へ更新し、旧Agentの拒否、順不同画像6枚の一括取得、LINE送信モックへの開始通知・最終返信を確認します。単体のWorkerテストでは通知設定、処理中の追加、キャンセル、再送重複排除も検査します。

## 稼働環境との照合

2026-09-11の読み取り専用`/healthz`は **version 0.3.0 / schemaVersion 4 / ok true** でした。公開版をこの機能・通信仕様へ合わせます。新しいDB migrationは追加せず、既にschema4の稼働DBには再適用しません。

Cloudflareのデプロイ照会は現行認証でエラー10000、旧Mac鍵の認証APIは401でした。旧Mac鍵はスタッフによるWindows移行で失効した記録があり、現行鍵はそのWindowsユーザーのDPAPIにあります。鍵の取り出し・更新をせず作業を進めました。稼働Workerの厳密なソース一致、現行Agentの認証と実行コードの一致は確認できていません。

本作業では本番の鍵変更、Workerデプロイ、稼働DBの変更、Bot設定変更を行いません。公開0.3.0と稼働版は版番号・schemaの一致を確認した範囲であり、デプロイ済みバイト列の一致を意味しません。

## 実機確認との区別

以前のWindowsネイティブでの文字2往復は**スタッフ**によるローカル修正版の確認です。今回の統合版でスタッフのWindows PCからLINEの画像・動画・整理を一通り実行した確認ではありません。

残る確認は、現行鍵を持つWindows PCでのLINE往復・画像・動画・追加添付・整理、Mac実Keychainを使った実運用、組織ポリシー下のWindows、Windows ARM64 / Windows 10、認証済みモデルの自然言語判断です。テスト用媒体とLINE APIモックの成功は実利用の成功と区別します。
