# 画像・動画の受信、解析と整理（0.3.0）

Mac / Windowsネイティブ共通です。個人LINEトークに対応し、Codexは読み取り専用のまま動きます。保存とコピーはAgentの固定処理が行います。

## 使い方

- 添付だけを送ると原ファイルを保存し、実際の受信件数をまとめて用途を確認します。未指示の画像説明は始めません。
- 「これから送る写真を比較して」と指示して添付すると、未完了の指示を会話から引き継いで解析します。
- 「この写真をイベント写真フォルダに整理して」と依頼すると、その名前のフォルダへコピーします。内容を見る必要のない単純な整理では画像解析を行いません。
- 解析・整理の開始通知は同じ作業で1回。処理中に追加の添付が届いた場合は先の結果を保留し、追加分とまとめて最終返信します。
- 通常の文章は最終返信のみ。「これから詳細ログを出して」で開始・進捗表示を継続設定し、「今回は詳細ログも出して」で今回だけ、「ログはもういい」で通常へ戻します。

最終受信から8秒待ち、1回最大30メッセージをまとめます。画像セットの未到着分は最大60秒待ちます。不足分があれば実際に届いた分だけを扱います。完了済みの古い依頼を新しい添付へ自動適用しないようルーティングで指示しますが、自然言語の判断はモデルに依存します。

## 保存先

`<workspace>/line-media/<会話ハッシュ>/<日本時間の日付>/<image または video>/<受付番号>/`

- `original.*`：LINE APIから得た元データ。LINE側で変換される場合があり、撮影原本と同一とは限りません。
- `preview-*.jpg`：画像は1枚、動画は6時点のプレビュー。
- `metadata.json` / `summary.md`：受信情報、SHA-256、フレーム時刻、要約。一括処理では同じ回答を各添付へ保存します。
- 会話フォルダの`catalog.json` / `index.md`：全受信一覧。直近30件の概要を回答へ渡します。
- `collections/<指定名>/<受付番号>.<拡張子>`：整理したコピー。原ファイルは残し、既存の異なる内容を上書きしません。同じ依頼の再試行でも重複コピーを作りません。

パス移動、symlink / Windows junctionによる脱出、Windowsの予約名や無効文字を拒否します。受信データはGit対象外で自動削除しません。PCの空き容量は利用者が管理します。同時に複数Agentを起動しないでください。

## 必要なものと制限

`ffmpeg`と`ffprobe`をインストールしてPATHへ追加します。MacならHomebrewの`brew install ffmpeg`、WindowsならWindows版ffmpegのbinフォルダをPATHへ追加し、各`-version`で確認します。プレビュー生成が失敗しても保存済み原ファイルを残し、未確認部分を推測しないようモデルへ伝えます。

画像はJPEG / PNG / GIF / WebPで20MiBまで。GIFは代表静止画です。動画はMP4 / MOVで200MiBまで、代表6フレームでの要約です。動画全場面の確認や音声文字起こし、音声単体・一般ファイル、外部コンテンツプロバイダー、グループトーク、Botからの画像動画返送には対応しません。

LINEの媒体保持期限を過ぎると再送が必要です。長期間PCを止めるためのクラウド媒体保管はありません。画像内容はプレビューとしてCodexに渡されます。

## 検証

`npm test`（Windowsは`npm.cmd test`）で生成したJPEG / PNG / MP4から実ffmpegのプレビューを作り、コピー・再試行・原データ保持を検査します。Workerテストは署名付きWebhook、D1のmigration、画像6枚の一括取得、LINE APIモック、通知と完了を通します。

ログイン済みCodexとの任意の確認は`npm run media:smoke`と`npm run conversation:smoke`です。モデルを呼びますが、LINE配信や本番Worker操作はしません。実機では画像・短い動画・フォルダ整理・追加添付・会話継続を送り、PCの原ファイルとコピーと返信を照合してください。今回のCI結果と以前の実機確認は[検証記録](release-0.3.0.md)で区別しています。
