# PC Codex秘書 セットアップ実施手順

更新日: 2026-09-03
対象: LINE公式アカウント → Cloudflare Worker / D1 → PC上のCodex App

## ゴール

LINEへ依頼を送ると、Codex Appの右側ターミナルに受信・処理・返信のログが流れ、結果がLINEへ返る状態を作る。

```text
LINE
  ↓ 依頼
Cloudflare Worker + D1
  ↓ 安全な取得
PC Codex秘書（gpt-5.6-luna / max）
  ↓ 結果
LINE
```

初回は次の規定値を使う。

| 項目 | 規定値 |
|---|---|
| LINE公式アカウント名 | PC Codex秘書 |
| 団体名 | PC Codex秘書 |
| 業種 | 個人 → 個人（架空）。確認画面で必要なら利用者が変更 |
| 利用者 | 1人 |
| 対象 | 個人チャットのテキスト |
| ワークスペース | このプロジェクトフォルダ1つ |
| 操作モード | 読み取り専用 |
| AIモデル | `gpt-5.6-luna` |
| 推論強度 | `max` |
| 同時処理 | 1件 |

## 作業分担

AIが、ページ移動、通常項目の入力、設定、ファイル作成、コマンド、D1、デプロイ、Webhook、検査、右側ターミナルの準備をまとめて行う。利用者へクリック単位で作業を頼まない。

LINEのセットアップでは、LINE関連のブラウザタブを常に最大1つにする。Business Manager、LINE公式アカウント作成、Official Account Manager、LINE Developersを同時に開き続けない。リンクによって新しいLINEタブが開いた場合は、必要な組織ID・ベーシックID・Channel IDなどの非秘密IDと完了状態を記録し、未完了の画面がある1タブだけを残して、それ以外のLINEタブを直ちに閉じる。利用者が開いているLINE以外のタブは閉じない。

利用者が行うのは次の場合だけとする。

- ログイン、パスワード、MFA、CAPTCHA。CAPTCHAは画像の選択肢をAIが判定・指定せず、問題全体を本人へ引き継ぐ
- 規約や法的事項への同意
- OAuthの許可
- LINEのSecretやTokenを公式画面で表示し、安全なローカル入力欄へ渡す操作

Secret、Token、パスワード、MFAコードはCodexの会話やLINEへ貼らない。

Secret Brokerへの既定の引き継ぎは、macOSクリップボードを一回だけ使うローカル経路とする。利用者がLINE公式画面の `[コピー]` でSecretまたはTokenをコピーした後、AIはクリップボードの内容を読み取らず、`npm run worker:secrets -- <mode> --clipboard` を起動する。Brokerが `pbpaste` から値をメモリへ受け取り、`shell: false` の `wrangler secret put` 標準入力へ直接渡し、成功・失敗にかかわらず `pbcopy` でクリップボードを消去する。値を会話、コマンド引数、環境変数、一時ファイル、出力へ載せない。

非表示TTYプロンプトを代替経路に使う場合は二段階で引き継ぐ。まずAIがBrokerコマンドを起動し、利用者が「入力内容は表示されません」という専用プロンプトを実際に確認する。利用者からプロンプト確認の返答を得るまでSecretやTokenを貼り付けさせない。ターミナルパネルを開いただけ、または通常のシェルプロンプトが表示されている状態を入力準備完了とみなさない。

SecretやTokenを通常のシェルへ誤って貼り付け、文字列が画面へ表示された、コマンドとして実行された、またはシェル履歴・スクロールバックへ残った可能性がある場合、その値は登録に使わず直ちに発行元でローテーションする。新しい値は専用プロンプトの表示確認後にだけ入力する。

## 開始時の確認

AIは作成を始める前に、まず今回のresource policyを `reuse_or_create` または `create_isolated` に固定する。通常セットアップは `reuse_or_create`、利用者がドキュメント試験、新規構築試験、既存とは接続しない構成を明示した場合は `create_isolated` とする。その後、現在のプロジェクト、`.setup/progress.json`、既存のLINE公式アカウント、Cloudflareアカウント、D1、Worker、Keychainを確認する。

`reuse_or_create` では既存リソースを候補として提示し、同名リソースを重複作成しない。`create_isolated` では2回目以降の試験で既存リソースが見つかることを正常とみなし、再利用候補として提示しない。既存確認は名前衝突と誤接続を防ぐためだけに使い、試験IDまたは日時を含む一意な名前で新規作成する。

途中から再開する場合も、最初からやり直さず、最後にAPIまたはCLIで確認できた地点の次から始める。

`create_isolated` で再利用してよいのは、ログインに使うLINE Business IDとCloudflareアカウントだけである。LINE公式アカウント、LINEビジネスマネージャー組織、Provider、Messaging API Channel、D1、Workerは試験専用に新規作成し、既存リソースへ接続しない。新規作成対象を開始前に一覧で固定し、resource manifestへ `resourcePolicy: "create_isolated"`、`testRunId`、`createdByNavigator: true` を記録する。

## 1. LINEの箱を作る

`create_isolated` では試験専用のLINEビジネスマネージャー組織を新規作成し、既存組織を選ばない。個人利用の既定案は次のとおりとし、空欄を並べて利用者へ丸投げしない。

開始前に、LINE Business IDへログインできることに加えて、ビジネス情報へ登録するメールアドレスの受信箱をその場で開けることを確認する。新規組織ごとに確認メールのリンク認証が必要であり、ここはAIが代行できない必須の本人操作である。受信箱へアクセスできない場合は、個人情報を入力して組織を作成する前に停止する。

| 項目 | 既定案 |
|---|---|
| 地域・所在国 | 日本 |
| 組織名 | `PC Codex秘書 文書テスト {testRunId}` |
| ビジネスタイプ | 個人事業主 |
| 屋号、フリガナ、事業主名、住所、WebサイトURL、電話番号、メールアドレス | 同じLINE Business IDが管理する既存組織の登録済みビジネス情報を複写 |

既存組織の登録情報を複写することは、既存組織やアカウント・チャネルを新規組織へ接続することではない。AIは複写対象の項目と登録先がLINE Business Managerの新規試験組織であることを示し、「この内容で新規組織へ入力してよいですか？」と一度だけ確認する。利用者が了承した場合だけ、既存組織から同じLINEサービス内の新規フォームへ入力する。不足項目または変更希望だけを利用者が公式フォームへ直接入力し、値を会話へ貼らせない。

### 既存ビジネス情報がない場合

新規のLINE Business IDなど、複写元が空の場合は次の提案値を使う。提案値は確定情報ではなく、利用者が確認するまで送信しない。

| 項目 | 提案値または入力方法 |
|---|---|
| 地域・所在国 | 日本 |
| 組織名 | `PC Codex秘書 文書テスト {testRunId}` |
| ビジネスタイプ | 個人事業主 |
| 屋号 | `PC Codex秘書`。実際に使用する屋号と異なる場合は利用者が変更 |
| 屋号フリガナ | `ピーシーコーデックスヒショ`。実際の読みと異なる場合は利用者が変更 |
| WebサイトURL | `https://github.com/Naofumi-1000ri/line-codex-secretary` |
| 事業主名・フリガナ | 法的な事実なのでAIは捏造しない。利用者が公式フォームへ直接入力 |
| 郵便番号・住所・建物名 | 利用者が公式フォームへ直接入力。建物名が任意なら空欄可 |
| 電話番号・メールアドレス | 利用者が公式フォームへ直接入力 |

AIは先に提案値を入力し、未入力の事実項目を一つずつ尋ねない。次のように一度だけまとめて引き継ぐ。

> 新規組織の基本項目を既定値で入力しました。事業主名・フリガナ、郵便番号・住所、電話番号、メールアドレスを公式フォームへ直接入力してください。屋号とWebサイトの提案値も確認し、実態と違う場合だけ変更してください。すべて確認できたら、規約に同意できる場合は `[同意して作成]` を押してください。

`[同意して作成]` には中間の確認画面がなく、押すと組織が即時作成され、登録したメールアドレス宛ての確認メール送信へ進む。AIはボタンを本人へ引き継ぐ前に、必須欄、試験専用の組織名、ビジネスタイプ、所在国を画面で検査する。利用者が先に押した場合も、新規組織名と発行された組織IDを検証できれば成功として続行し、同じ組織を重ねて作らない。作成後は利用者が受信した確認メールのリンクを開き、メール認証が完了するまでアカウント・チャネル接続へ進まない。

### AIがまとめて行うこと

1. `create_isolated` の場合は `business.line.biz` の正しい画面で試験専用組織の作成フォームを準備し、上記の既定案を提示する。了承後、既存組織の登録済みビジネス情報を新規フォームへ入力する。不足・変更項目の入力、規約同意、最終作成は利用者が行う。作成後は新規組織IDを記録し、利用者による確認メールの認証完了を画面で検証する。
2. `manager.line.biz` の正しい画面を開く。
3. resource policyを確認する。`reuse_or_create` の場合だけ既存の `PC Codex秘書` を再利用候補として検索する。`create_isolated` の場合は既存を衝突・誤接続の検査対象として確認するが、候補に出さない。
4. 存在しなければ、アカウント名、団体名などの通常項目を入力する。業種は `個人 → 個人（架空）` を既定値にし、確認画面で必要なら利用者が変更できると伝える。
5. `create_isolated` では作成済みの試験専用ビジネスマネージャー組織を選ぶ。既存組織IDが表示される選択肢は使わない。
6. 連絡先メールアドレス欄がある場合は、会話へ値を貼らせず、利用者がLINE公式フォームへ直接入力できる状態にする。
7. 同じフォームの `[確認]` が利用規約への同意を表す場合は、メールアドレスの直接入力、入力内容・規約の確認、同意できる場合の `[確認]` までを一つの目的として利用者へ依頼する。メールアドレス入力だけで一度停止し、続けて `[確認]` だけを依頼する二往復には分けない。
8. 確認画面へ遷移したらAIが入力内容を再検査する。`create_isolated` では接続先のLINEビジネスマネージャー組織も新規試験用であることを確認し、既存組織IDが表示されていたら作成を確定しない。任意の情報配信・友だち追加はBot構築に不要なので既定値をオフにする。利用者が明示的に希望した場合だけオンにし、最終 `[完了]` は本人へ引き継ぐ。
9. 作成後に「情報利用に関する同意」など追加の同意画面が連続して表示される場合がある。表示中の同意画面ごとに取得・利用される情報の要点を伝え、利用者が内容を確認して同意可否を決めるまで停止する。「一度同意したから完了」と判断せず、管理画面のURLとアカウントホームが表示されるまで同じ検査を繰り返す。
10. すべての追加同意を通過して管理画面へ入った後、Messaging APIを有効にし、ProviderとChannelを確認する。
11. Provider作成時にプライバシーポリシーURLと利用規約URLの登録画面が表示された場合は、両項目が任意かを画面で確認する。利用者から正規URLの指定がなければ値を作らず空欄のままにし、後から変更できることを伝える。新規ProviderとChannelの確定まで `[OK]` が2回以上続く場合があるため、1回で完了とみなさず、`ステータス: 利用中` とChannel IDを検出するまで本人へ表示中の確認を引き継ぐ。
12. Messaging API有効化後の管理画面にはChannel Secretが平文で自動表示される場合がある。認証済み画面にSecretが表示されること自体をセットアップ失敗とは扱わず、ブラウザ操作も停止しない。ただし、AIは値を目的として読み取ったり、再掲、ファイル保存、コマンド引数化、別サービスへの送信をしたりしない。画面取得に偶発的に含まれた場合は、値をそれ以上利用せず、利用者が公式画面からSecret Brokerへ直接渡す。権限のない相手や意図しない保存先へ送信した場合、または利用者がAIからの完全隔離を要件にした場合だけ再発行する。

### 利用者が行うこと

ログイン、MFA、CAPTCHA、公式フォームへの連絡先メールアドレスの直接入力、規約同意、任意の情報配信設定の選択、アカウント作成の最終確定、作成後に連続して表示される各情報利用同意の判断を行う。CAPTCHAはAIへ解かせたり画像マスの指定を求めたりせず、利用者が表示内容に従って完了する。メールアドレスは会話へ貼らない。AIは本人操作が必要な画面まで準備し、フォーム入力時は次のように一つの目的として依頼する。

> メールアドレスをLINE公式フォームへ直接入力し、入力内容と利用規約を確認してください。同意できる場合は `[確認]` を押し、確認画面が表示されたら「確認画面になった」と送ってください。

### 完了条件

- LINE公式アカウント `PC Codex秘書` が存在する。
- Messaging API Channelが存在する。
- Channel IDをAIが確認できる。

## 2. ネットの受付を作る

Cloudflareは、次の3経路を最初に判定する。Wranglerが認証済みでも、それだけを標準状態とみなさない。

| 開始状態 | 案内 |
|---|---|
| Wrangler認証済み | `wrangler whoami` で対象Account IDと必要scopeを確認する。ダッシュボードを開かない場合も、再利用するのはログイン中のCloudflareアカウントだけであり、今回新規作成するWorkerとD1の名前を利用者へ示す。 |
| CloudflareアカウントはあるがWorkers未設定 | 利用者がログイン、MFA、WranglerのOAuth許可、表示されたWorkers利用規約への同意可否を判断する。`workers.dev` サブドメインが未設定なら、AIが公開名の候補を用意して初期設定へ案内する。 |
| Cloudflareアカウント自体がない | AIがCloudflare公式の無料アカウント作成画面を開く。利用者がメールアドレスとパスワードを公式画面へ直接入力し、規約、アカウント作成、確認メール、MFAを本人操作で完了する。その後は「アカウントはあるがWorkers未設定」の経路へ進む。 |

アカウント作成やプラン選択画面では無料プランを既定案にし、有料契約、支払い情報、ドメイン購入などBot構築に不要な操作は行わない。料金が発生し得る選択肢しか表示されない場合は停止して利用者へ説明する。

Worker名とD1名の既定案はどちらも `line-codex-secretary-{testRunId}` とする。`create_isolated` では既存の同名または類似リソースを再利用せず、利用可能な一意名に調整して必ず今回専用に新規作成する。

`workers.dev` サブドメインはWorker名とは別のアカウント共通設定であり、URLとして公開され、世界で一意になる。未設定の場合は、AIが個人情報を含まない候補（例: `line-codex-{短いランダム文字列}`）の利用可否を確認してから、Account ID、Worker名、D1名と一緒に次のように一度だけ確認する。項目ごとに質問を分けない。

> Cloudflareはこのアカウントを使い、WorkerとD1を今回専用に新規作成します。名前はどちらも `line-codex-secretary-{testRunId}`、初回だけ必要な公開 `workers.dev` サブドメインは `{候補}` にします。この内容で進めてよいですか？

既存の `workers.dev` サブドメインがある場合、それはログインアカウントの公開URL基盤として再利用してよいが、既存WorkerやD1の再利用を意味しない。AIは新規リソースの作成前後に、対象Account ID、resource policy、新規作成する名前、作成された非秘密IDとURLを明示する。

### AIがまとめて行うこと

1. Worker、D1 migration、設定ファイルを準備する。
2. `wrangler whoami` を値の再掲なしで検査し、上記3経路のどこから開始するかを決める。
3. 必要な場合だけCloudflare公式画面またはWranglerの認証を開始する。アプリ内ブラウザからlocalhost callbackへ戻れない場合は、待たずにdevice authorizationへ切り替える。
4. 対象Account ID、resource policy、Worker/D1名、未設定時の `workers.dev` 候補をまとめて提示し、一度だけ確認する。
5. `create_isolated` ではD1を今回専用に新規作成する。`reuse_or_create` では保存済みIDとの一致を確認した場合だけ再利用し、migrationを適用する。
6. `workers.dev` が未設定なら本人による規約同意後に初期設定を完了し、Workerをデプロイする。
7. 正確な `workers.dev` URLの `/healthz`、D1 schema version、作成されたリソースIDを検査する。

### 利用者が行うこと

必要に応じてCloudflare無料アカウントの作成とメール確認を行い、ログイン、MFA、OAuth、Workers利用規約、公開 `workers.dev` サブドメインを確認して本人判断が必要なボタンを押す。メールアドレス、パスワード、MFAコードは会話へ貼らず公式画面へ直接入力する。

### 完了条件

- `/healthz` が `ok: true` を返す。
- D1のschema versionを取得できる。
- Worker URL、D1 ID、Cloudflare Account IDが進捗ファイルに記録される。

## 3. LINEの鍵を安全に登録する

### AIがまとめて行うこと

1. Channel SecretとChannel Access Tokenの登録先を準備する。
2. 入力内容を画面、履歴、引数へ残さないローカル入力を開く。
3. Cloudflare Secretの存在を確認し、実際の認証処理で正しさを検査する。
4. PC Agent tokenを生成し、平文はmacOS Keychain、ハッシュはWorkerへ保存する。

### 利用者が行うこと

LINE Developersの公式画面でChannel SecretとChannel Access Tokenを表示し、指定されたローカル入力欄へ入れる。会話欄やLINEには貼らない。

### 完了条件

- 必要なWorker Secret名がすべて存在する。
- PC AgentがWorkerの認証付きhealth APIへ接続できる。
- Secretの値そのものがログや進捗ファイルに残っていない。

## 4. LINEと受付をつなぐ

### AIがまとめて行うこと

1. WorkerのWebhook URLをLINEへ設定する。
2. Webhookを有効にしたら保存通信が終わるまで待ち、画面を再読み込みしてもスイッチがオンのままか確認する。オン直後に検証や画面遷移を行わない。その後、LINEの `[検証]` が成功し、署名付きイベントがD1へ届くことを確認する。
3. 一度だけ使える6桁のリンクコードを発行する。

### 利用者が行うこと

LINEで `PC Codex秘書` を友だち追加し、AIが発行した `/link 123456` 形式のコードを送る。

### 完了条件

- LINEへ「PC Codex秘書と安全にリンクできました」と1回だけ返る。
- D1に有効な所有者が1人だけ登録される。
- 使用済みリンクコードが再利用できない。

## 5. PCのCodex秘書を起動する

### AIがまとめて行うこと

1. 許可フォルダがこのプロジェクトだけであることを確認する。
2. Codex App Serverの読み取り専用smoke testを行う。
3. 新規スレッド、再開スレッド、各ターンで `gpt-5.6-luna` を明示し、各ターンを `max` に固定する。
4. Codex Appのこのタスクに右側ターミナルを開く。
5. 右側ターミナルで次を起動し、表示したままにする。

```bash
npm run secretary
```

パネルが表示されない場合はCodex Appを一度再起動し、同じタスクを開いてからターミナル表示を再試行する。

### 利用者が行うこと

通常はなし。停止したいときだけ、起動したターミナルで `Ctrl+C` を押す。

### 完了条件

右側ターミナルに次が表示される。

```text
🟢 ONLINE     LINEからの依頼を待っています
🔗 Codex接続  会話を引き継ぐセッションサーバーに接続済み
```

## 6. LINEから一往復を確認する

### 利用者が行うこと

LINEから安全な読み取り依頼を1件送る。

```text
このプロジェクトを3行で説明してください
```

続けて、会話継続を確認する短い依頼を送る。

```text
さっきの説明を一言にしてください
```

### LINEで見える流れ

```text
📨 PC Codexへ送信しました
🖥️ PC Codexが受信しました
🧠 Codexが確認中です…
✅ Codexから返信が届きました
```

### 右側ターミナルで見える流れ

```text
[時刻] 📩「このプロジェクトを3行で説明してください」のメッセージを受信
[時刻] 🧾 受付番号  J...
[時刻] 🔗 Codex接続  前のLINE会話を引き継ぎました
[時刻] 🧠 Codex処理中  回答を作っています…
[時刻] ✅ LINE返信  「...」  (処理時間)
```

### AIが検証すること

- Webhook eventとjobが重複していない。
- 受付番号がLINEと右側ターミナルで一致する。
- 2件が同じCodex thread IDを使う。
- モデルが `gpt-5.6-luna`、推論強度が `max` である。
- 結果が各依頼につき1回だけLINEへ返る。
- Secret、Token、ユーザーIDがログに出ていない。
